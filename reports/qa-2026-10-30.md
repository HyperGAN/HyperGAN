# HyperGAN 2.0.0 QA Report (Round 1) — 2026-10-30

## Executive Summary & Verdict

- **QA Round 1 Verdict:** **FAIL** (blocked on long-horizon pure-transformer critic/formulation stability; candidate fix identified upstream in **ParticleGAN**).
- **What Passed:** Multi-GPU (`2× NVIDIA RTX A6000`) NCCL data-parallel execution, periodic distributed checkpointing across mid-run `git` commits, elastic cross-topology resume (`1 <-> N` GPUs), Tailscale MagicDNS Web Observatory (`0.0.0.0:8765`), packaged recipe bare-name CLI resolution (`hypergan train cifar10-transgan`), and coalesced 10-scalar multi-GPU GAN health telemetry (including live `optimizer/d_guard_ratio` spike-guard damping).
- **What Failed:** Both long-horizon 2-GPU validation runs (`batch_size = 256`) of the pure-transformer packaged recipe (`src/hypergan/models/cifar10-transgan.toml`) collapsed under ParticleGAN's `ka2` critic formulation:
  1. **Run B (`marble-anchor`, `lazy_k = 8`, `runs/cifar10-transgan-2gpu`):** Reached **`FID-50k = 37.41`** at step `7,500`, entered zero-margin stagnation (`D_adv ≈ G_adv ≈ ln(2) = 0.6931`) right after `ka2` call `800` (**step `6,392`**), drifted unanchored relativistic logits to **`+19.00`**, and blew up at **steps `12,760–12,800`** (`GP = 43.77 -> 104.03`, `grad_norm/critic = 11,295.7`, `diversity/ratio = 2.04` `tanh` saturation).
  2. **Run C (`coral-crest`, `lazy_k = 1` + `ema_critic.eval()` + ParticleGAN spike guards `5.0 / 200`, `runs/cifar10-transgan-2gpu-lazyk1`):** Suffered an instantaneous **`7,880×` single-step penalty shock at exact call `800` (step `800`)** (`GP: 0.0028 -> 22.0639`, `grad_norm/critic = 164.55`, `optimizer/d_guard_ratio = 0.0433`), over-constrained critic margins (`FID-50k = 83.60` at step `2,500`), and collapsed completely at **steps `4,530–4,570`** into a **constant-function `[CLS]` self-attention sink** (`D(x) ≡ +5.589783`, `grad_norm/critic = 2.47e-8`, `GP = 3.47e-22`, **`FID-50k = 227.63`** at step `5,000`).

## 3. Root-Cause Findings (Upstream ParticleGAN & Pure-Transformer Critic)

### Finding P1 — `KA2GradientPenalty` Dimension Normalization Mismatch (`3,072×` / `55.4×` Jump at Call `800`)
In `particlegan/ka2.py` (`KA2GradientPenalty._k3p_penalty`), `phase = "a"` (`calls 1..799`) and `a_term` normalize input gradients by image dimensionality $d = \text{numel}(x_0)$ ($d = 3 \times 32 \times 32 = 3{,}072$ on CIFAR-10, $\sqrt{d} = 55.43$; on $128\times 128$ RGB, $d = 49{,}152$, $\sqrt{d} = 221.70$):

```python
# Normalized by dimension / sqrt(dimension): caps ||grad_x D||_2 at sqrt(3072) * kappa = 55.43
a_term = (sq_r / dimension).mean() + (n_f / dimension ** 0.5 - self.kappa).relu().square().mean()

# UNNORMALIZED Euclidean L2 norms n_r, n_f: caps ||grad_x D||_2 at kappa = 1.0 (55.4x tighter!)
b_term = F.relu(n_r - self.kappa).pow(2).mean() + F.relu(n_f - self.kappa).pow(2).mean() + weight * prox
```

- On 2D toy tasks ($d = 2, \sqrt{d} = 1.414$), `n_r` and `n_r / sqrt(d)` match closely.
- On $32\times 32$ RGB images ($d = 3{,}072$), switching on `0.5 * b_term` at **call `800`** (even with `prox = 0` on that first blended call!) tightens the critic Lipschitz threshold by **`55.4×`** (`||∇_x D||_2 <= 1.0`, or `0.018` per pixel), causing the exact **`7,880×` single-step `GP` jump (`0.0028 -> 22.0639`)** observed at step `800` of Run C and the step-`6,392` stagnation transition in Run B.

### Finding P2 — Post-Shock `sur_base` Calibration Thrashing (`59` EMA Reseeds)
`KA2StepRecord` calibrates `sur_base` from the first `BASE_WINDOW = 24` calls *after* call `800` (`steps 800..824` under `lazy_k = 1`). Because step `800`'s `gn_D = 164.55` spike inflates Adam's second moment `v_t` while `b_term` immediately crushes subsequent gradients (`gn_D = 0.039` at step `820`), `sur_base` locks onto an artificially depressed value (`0.03006`). Once normal gradients resume, `surprise_ratio = median(sur) / sur_base` stays at `5.5–24.2×` (`>> REL_HI = 3.0`), permanently disabling `w = 0.0`, pinning `alpha = 1.0`, and firing `59` `ema_reseeds` in 4,200 steps.

### Finding P3 — Pure-Transformer `[CLS]` Self-Attention Sink Collapse (`D(x) ≡ +5.5898`)
Inspecting the saved step-`5,000` discriminator weights in `runs/cifar10-transgan-2gpu-lazyk1` revealed how a pure-transformer `[CLS]` critic escapes strong every-step input-gradient penalties (`lazy_k = 1`):
- All transformer weight matrices maintained normal Frobenius norms (`23.0–29.7`), and `critic_score.weight` had norm `0.862`.
- However, in `final_block_att` (the final self-attention block where the prepended `[CLS]` token pools the 64 spatial tokens), **all 4 attention heads drove `logit(CLS -> CLS)` `+23` to `+120` nats higher than every image token**:
  - `(CLS->CLS logit, max CLS->image logit)` per head at step `5,000`: **`[(+8.47, -50.75), (-6.64, -30.02), (-2.48, -53.68), (+30.43, -89.67)]`**
  - Resulting `softmax` probability on `CLS -> CLS`: **`[1.0, 1.0, 1.0, 1.0]`** (`0.0` in float32 on all 64 image tokens!).
- By attending `100%` to `[CLS]` and `0%` to image patches, $D(x)$ collapsed to an exact constant function $D(x) \equiv +5.589783$ with $\|\nabla_x D(x)\|_2 = 2.47\times 10^{-8}$, achieving **zero gradient penalty (`3.47e-22`)** at the relativistic saddle loss $\ln 2 = 0.693147$ while starving the generator of all adversarial gradients (`FID-50k = 227.63`).
- Note also that `src/hypergan/models/cifar10-transgan.toml` currently omits `defaults = "particlegan"` (unlike `cifar10-tiny-transformer.toml`, `image-folder-128.toml`, and `colorization-128.toml`), so it exercised the legacy `ka2` + relativistic unanchored-logit path rather than `bispf_optimized`.
