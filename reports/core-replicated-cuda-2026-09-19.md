## Implemented contract

The `cuda-replicated-nccl` execution profile requires recipe `training.device="cuda"`, at least two ranks, enough visible GPUs and an evenly divisible global/microbatch. Rank *r* owns visible `cuda:r`. Structural profile checks remain Torch-free. Runtime preflight constructs actual CUDA replicas through the existing independent worker broker, checks common runtime/source/data/state identity and exits without updates or run artifacts. Public `train`/`resume` still use the native single-process adapter; internal Python wrappers now accept and persist either replicated profile.

Backend-aware collectives and `ReplicatedTrainer` retain the existing CPU entry points while placing numerical tensors, gradient-presence reductions and metrics on rank-owned GPUs. The same NCCL group carries ordered numerical and metadata collectives. Device binding happens before group construction and is restored before metadata exchanges after custom hooks. There is no second control process group. Complete initialization, updates and restore synchronize CUDA before acknowledgement; asynchronous failures cannot be reported as complete logical steps.

The numerical equations, explicit gradient averaging, global RA, unique VICReg, lazy higher derivatives and accumulated replay remain shared with CPU correctness fixtures. Model/prior/auxiliary parameters, both Adam optimizers and EMA are replicated. Global data construction and sampler state remain on CPU before rank slicing and transfer. CUDA prior/penalty streams and global CUDA RNG are retained during replay. The current equality checks and duplicated data decoding prioritize correctness; this is not a throughput claim.

Checkpoint preparation converts complete rank payloads to CPU tensors before hashing and serialization. Common runtime identity records CUDA/cuDNN/NCCL, precision/determinism settings, visible device inventory and ordered rank-to-device UUID mapping. Each payload separately records its own CUDA current-device/RNG state. Restore rejects a wrong rank binding, validates a copied candidate, checks complete live state and only then reports readiness. Parent-only commit authority, failed-update poisoning and independent broker supervision remain intact. Existing payload caps still apply, and NCCL stages serialized object bytes through GPU memory; transport is not sharded or designed as a cluster storage protocol.

Preview capture copies snapshots to CPU; the group-free renderer explicitly reconstructs its prior on CPU. Final inference preserves copied-state/RNG isolation and supported bundles remain CPU-loadable. The [CUDA guide](../docs/replicated-cuda.md) supplies an internal two-GPU stop/resume example and explains these limits.
