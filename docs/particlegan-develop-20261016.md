## Clean-package correction

The first full installed CI run exposed two real fallback bugs beyond the initial focused source checks. `distributed_training` installed a global compatibility wrapper over `training.particlegan_recipe`; importing it replaced selected BCAP/BISPF with bare KA2. That shim is removed: the canonical factory already supports the pinned API. Separately, `config_values`/`numerical_values` omitted `particlegan_trainer`, causing public training, manifests, worker transfer and resumed configuration to drop the selector. Both serializers now retain it, and fingerprints distinguish trainers while configurations without a selector retain their historical values.

Regression coverage includes replicated-module import/reload, serialization of all four presets, public training/checkpoint/resume with BCAP, changed-engine resume rejection, conditional BISPF refusal before creating a run and CLI module import. Native-only presets are refused before allocating replicated workers: the replicated optimizer loop does not implement their protected-gradient/sample-row protocol, so it must not silently train an incomplete adaptation. Legacy configurations still support their existing replicated path. A source-distribution-built wheel is tested outside the checkout with normal VCS-installed ParticleGAN metadata; source path injection is not used.

A missing `Optional` annotation import in the unchanged CLI was also corrected so public installed entry points can import. The follow-up also addresses the broader CI failures described below; new regressions run in the existing CPU reference job. Adding a dedicated pinned-trainer workflow job was rejected by GitHub because the OAuth app lacks workflow scope; that unpushed workflow proposal is retained locally, and the published workflow is unchanged.
