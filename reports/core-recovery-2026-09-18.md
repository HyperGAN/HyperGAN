# Core recovery and image data — 2026-09-18

This checkpoint advances the CPU core: deterministic image-folder input, complete training state, explicit resume, immutable attempt artifacts and live CLI progress. Three subagents implemented and reviewed separate parts, with coordinator integration on `develop` through [PR #304](https://github.com/HyperGAN/HyperGAN/pull/304) and [PR #305](https://github.com/HyperGAN/HyperGAN/pull/305). No GPU or paid compute was used.

## Delivered workflow

- Image preflight: `hypergan data-check CONFIG` inventories local files, validates decoding and declared preprocessing, records content hashes/class labels, and imports no training runtime. Optional `image` dependencies stay out of base installs. [PR #304](https://github.com/HyperGAN/HyperGAN/pull/304) merged with all required checks passing; its installed wheel passed 57 tests.
- Recoverable CPU runs: `train --checkpoint-every N --stop-after-steps N` and `resume RUN_DIR` retain the original numerical schedule. Atomic complete checkpoints capture model/prior/EMA/optimizer state, registered buffers and modes, learning-rate bases, RNG streams and data position. A half-completed D/G update never replaces the last complete generation.
- Compatibility: resume validates configuration, runtime/topology, available implementation hashes and data/preprocessing/class-map identity. Inference bundles cannot be used as training checkpoints. Unsupported custom data/objective recovery is reported explicitly; those configurations can still train.
- Artifact history: every attempt has a monotonic index and unique identifier; replaying an older checkpoint preserves later files. Samples publish atomically without replacing an existing output. Inference and progress callbacks preserve the global CPU RNG streams.
- Observable progress: versioned manifests/events distinguish observed updates from the last durable checkpoint, checkpoint interval and possible lost updates. CLI JSONL progress is flushed before completion. Cooperative wall-time stops, concurrent-writer rejection and failure status are tested.

[Recovery commands](../docs/recovery.md) and [image-data details](../docs/image-data.md) define the supported interfaces. These are CPU contracts, not image-quality, GPU or cluster qualification.

## Frozen first image candidate contract

The selected recipe is [scout/direct_gan.yaml](https://github.com/255BITS/ParticleGAN/blob/f946b4ed468ff3b3eae5a3bca11411d5725f1181/configs/cifar_particle_ddgan/scout/direct_gan.yaml) plus the defaults and loop in [train_cifar_particle_ddgan.py](https://github.com/255BITS/ParticleGAN/blob/f946b4ed468ff3b3eae5a3bca11411d5725f1181/experiments/train_cifar_particle_ddgan.py). Older similarly named image AE trainer defaults differ; do not mix their learning rates into this recipe.

- G contract: float32 `z[B,64]` → RGB `image[B,3,32,32]`, tanh range `[-1,1]`. Width 32; latent linear projection into 128×4×4; three nearest-neighbor upsample/residual blocks with latent embeddings; final RGB convolution/tanh. Source [DirectGenerator](https://github.com/255BITS/ParticleGAN/blob/f946b4ed468ff3b3eae5a3bca11411d5725f1181/lib/image_particle_autoencoder.py#L27), file blob `46526b19e44778a450d53ad480e4a3f0c9ea6512`.
- D contract: RGB candidate → one scalar per example; no labels, encoder or noisy input. [DirectDiscriminator](https://github.com/255BITS/ParticleGAN/blob/f946b4ed468ff3b3eae5a3bca11411d5725f1181/lib/image_particle_autoencoder.py#L67) wraps a trainable pixel/feature-head critic with **frozen ImageNet ResNet18 features** and fixed all-zero image context. Preserve frozen weights AND BN evaluation mode while retaining gradients through features to the candidate, including b-cap's double backward. Pin and record pretrained weight identity/download behavior separately. Supporting [feature critic](https://github.com/255BITS/ParticleGAN/blob/f946b4ed468ff3b3eae5a3bca11411d5725f1181/lib/image_moonshots.py#L71), file blob `e6aee0069918493f06d586bb2dd8dd4a65a2b007`; [residual blocks](https://github.com/255BITS/ParticleGAN/blob/f946b4ed468ff3b3eae5a3bca11411d5725f1181/lib/image_ddgan.py), file blob `d2ad1db2401793f6038ce9448fa32488f8abac3f`.

## Recovery reviewer checklist against current foundation

References below are `src/hypergan/training.py` before the core recovery patch.

1. Complete checkpoint ownership: G, D, every owned encoder/auxiliary, prior parameters and buffers, EMA graph/prior, both optimizers with parameter-group identity, original `base_lrs`, total schedule horizon, global step/lazy-regularization phase, and data position/order/identity. Current EMA inference bundles intentionally lack this state and cannot become resume checkpoints by relabeling.
2. Update atomicity: D `step()` at line131 precedes G `step()`, EMA and counter commit at lines158–164. Exceptions/signals between them leave a half update. A recovery checkpoint must represent the last fully completed D+G+EMA boundary; never serialize live partially mutated state in an exception handler. Record attempted step separately from durable step. Use atomic generation publication/pointer updates and test failed writes/truncated checkpoints.
3. RNG: preserve named data/prior/penalty generators AND global Torch/Python/NumPy states for supported custom components/data. Restore after constructors, data initialization and `load_state_dict`, because those may consume RNG. Include custom data's declared state or reject exact resume; deterministic identity alone is not a cursor. A callable's hidden state is not captured merely by rejecting trainable nn.Module objective parameters/buffers.
4. Schedule/optimizer: LR at lines109–113 depends on original total `steps`. Attempt limits must not shorten the total schedule. Preserve original base LRs separately; deriving them from already-annealed restored optimizer groups changes future updates. Test a split that crosses the cosine/lazy-penalty boundary, compare all Adam moments/prior state/EMA and next sampled batch, not only final G loss.
5. Observers: inference construction and custom eval forwards can consume global RNG. Periodic previews must isolate and restore those streams; inference seeds should also cover custom stochastic eval behavior. Preview failures must not corrupt the durable training generation.
6. Custom model buffers/modes: state_dict includes registered buffers but not train/eval flags or arbitrary Python caches. Keep the defined frozen-module mode policy; BatchNorm/dropout plus stateful auxiliaries expose false guarantees hidden by deterministic MLP tests. State that exact recovery applies only to the implemented state contract; unsupported custom data/objectives may still train with an explicit unsupported-recovery warning.
7. Compatibility and lifecycle: compare resolved recipe, runtime/profile, stable component/source identity and dataset content/class map/preprocessing identity before loading state. Changed data content with unchanged path must fail. Preserve old immutable samples/checkpoints when resuming older generations. A manifest's `last_durable_step` must remain truthful even if failure occurs after a numerical update but before event/manifest persistence.
