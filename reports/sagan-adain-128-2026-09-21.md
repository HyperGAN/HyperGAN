# SAGAN/AdaIN generator for the 128px ResNet experiment

The generator is a standalone native HNDL configuration:
[`sagan-adain-generator-128.hndl`](../examples/networks/sagan-adain-generator-128.hndl).
The [paired recipe](../examples/sagan-adain-resnet-multiscale-128.toml) retains
the working fixed-context ResNet discriminator and training settings.

One latent sample of width 128 splits into content 64 and style 64. The content
half projects to 512×4×4; the style half feeds 11 independent affine projections
for AdaIN. There is no additional noise input or random noise injection.
HNDL's native `adaptive_norm` computes population spatial instance statistics,
then applies `(1 + delta_gamma) * normalized + beta` from each style projection.

Five residual nearest-neighbor upsampling blocks produce 128px RGB. Their
widths are 512/256/128/64/32. All 32 linear/convolution nodes use spectral
normalization. At 32px, pooled self-attention uses 1024 queries and 256 keys/values,
with a learned scalar gain initialized to zero. The architecture has 85 native
HNDL nodes and 8,386,180 trainable parameters. This is an unconditional
SAGAN-style/AdaIN hybrid, not an ImageNet SAGAN or StyleGAN reproduction.

## Launch

```sh
~/dev/hypergan/training-runs/start-sagan-adain-resnet-multiscale-128.sh
```

- Physical GPU1: `GPU-548116b 7-9dbe-de 58-b 3d 9-a 6e 27b 0f 74ce`.
- Local recipe: `~/dev/hypergan/training-runs/logos-sagan-adain-resnet-multiscale-128/sagan-adain-resnet-multiscale.toml`.
- Editable networks beside it: `generator.hndl` and `discriminator.hndl`.
- New run: `~/dev/hypergan/training-runs/train-sagan-adain-resnet-multiscale-128`.
- Existing HNDL0.4 environment: `~/dev/hypergan/training-runs/dcgan-multiscale-128-env`.
- Batch 64, target 200,000 updates; preview every 100, checkpoint every 1,000.

The local TOML was derived directly from the user's working recipe. Its only
configuration changes are generator and run name; the discriminator source is
byte-identical. Dataset, prior, loss, optimizer, batch size and seeds are
unchanged. Changing the generator also changes initialization RNG consumption;
this is an architecture comparison, not identical initial discriminator weights.
The working job on GPU0 was left running. The new long run has not been started.

## Validation

Eight dedicated CPU tests pass on published HNDL0.4.0: output shape/range at
batches 1/3, gradients into both latent halves, all style-affine inputs, an
independent population-AdaIN formula check, eval batch independence, no RNG
consumption in train/eval forward, zero-gate identity and subsequent attention
learning, and independent deepcopy/EMA after an optimizer step.

The actual CUDA recipe completed eight batch 64 updates and resumed from its
checkpoint for eight more. All losses were finite. All 61 generator parameter
tensors changed, including every style projection and attention projection.
The attention gain moved from 0 to -0.00247263 by step 16. All four discriminator
heads updated, while all 122 backbone state tensors stayed bitwise unchanged.
Lazy b-cap execution, checkpointing, CPU EMA previews and six diversity metrics
all completed. Peak allocated CUDA memory was 17.71GiB; reserved 19.94GiB.

At step 16, the 16-sample EMA preview had full-resolution diversity ratio 0.672736
and pooled 4 ratio 0.446778. These early measurements verify observation delivery;
they do not establish quality or long-term protection against collapse.

Spectral normalization updates its power-iteration buffers during training,
without random draws. Successive training outputs can therefore differ for the
same latent. EMA averages original weights and copies buffers; no claim is made
that its copied spectral estimate exactly normalizes the averaged weights.
